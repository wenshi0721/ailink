你是一位 Android 稳定性工程师。任务：**定位并修复一个"容器停止/重启时 App 闪退"的崩溃**。

## 背景

项目：`D:/data/project/jiuguan`，Android 客户端「接入助手」（包名 `com.jiuguan.ailink`）。
它在手机里用 proot 跑一个 Ubuntu 容器，容器内用 Xvfb 启动 Linux 版 QQ + NapCat，App 通过 `ws://127.0.0.1:3001` 与 NapCat 通信。

版本现状：`1.1.7`，`BASE_VERSION_CODE = 27`，debug 变体自动 +1（=28）。工作区干净，HEAD = `0506bdf`。

## 崩溃现象

- **用户点「停止 QQ」或系统自动重启容器时，App 闪退**。
- 1.1.7 引入"网络恢复即重启容器"后，重启频率上升，闪退变得频繁。
- 崩溃时机集中在**容器停止/重启**，日常聊天时正常。
- **目前没有任何 Java 堆栈**。

## 已经做过的加固（这些不要再重复做）

1. `shutdown()` / `onDestroy()` 每一步已 `runCatching`；
2. `QqBridgeService.start/stop/restart` 已包 `runCatching`（含 Android 12+ 后台启动前台服务的限制）；
3. `NetworkWatcher` 的系统回调整体已 `runCatching`；
4. 日志导出已移到 IO 线程（原来主线程读几 MB 日志）；
5. `AiLinkApp.installCrashLogger()` 已安装 `Thread.setDefaultUncaughtExceptionHandler`，把栈写入 `SessionLog`（tag=`crash`）。

## 你的第一步：先取证据，不要先改代码

按顺序做，每步的产出要写进最终报告：

1. 构建并安装 debug 包：
   ```bash
   cd android && ./gradlew assembleDebug
   adb install --no-streaming -r app/build/outputs/apk/debug/app-debug.apk
   ```
2. 复现：运行时页 →「停止 QQ」→「启动」，反复 5–10 次；再断开网络 30 秒后恢复。
3. 闪退后重新打开 App → 运行时页底部「日志与诊断」→「导出日志文件」，搜索 `[crash]`。
4. 若 `[crash]` 不存在，改用系统通道：
   ```bash
   adb logcat -b crash -d > crash.txt
   adb shell dumpsys dropbox --print data_app_crash > dropbox.txt
   ```
5. 把拿到的栈与"崩溃前最后 20 行会话日志"贴进报告。

**如果确实无法复现或拿不到栈，请直接说明，并给出下一步取证方案，不要用"猜测 + 大量改动"来冒充修复。**

## 值得优先验证的假设（按可能性排序）

A. **`KeepAlive` 竞态**：`android/engine/.../service/KeepAlive.kt` 的 `acquire()` / `release()` **没有同步**，内部是"判空 → 赋值 → 加锁"的 check-then-act。main 线程（`onDestroy`）与 IO 线程可能并发进入，导致 `WakeLock under-locked`。
B. **服务被重复 stop/start**：日志里每次重启都会重新打印 `[keepalive] bot 已获取` + `[keepalive] qq 已获取`，说明服务实例被重建。若同一时刻既 `stopSelf()` 又 `startForegroundService()`，可能触发 `ForegroundServiceDidNotStartInTimeException`。
C. **`stopForeground(REMOVE)` → `stopSelf()` 时序**（`QqBridgeService.kt:1024`）。
D. **Compose 重组期间的读取**：`RuntimeScreen` 在组合中调用 `vm.logSummary()` / `vm.logTail()`，后者会读文件尾部 16KB（仍在主线程）。
E. **`SessionLog` 锁内 IO 死锁**：`add()` 是 `@Synchronized` 且在锁内做文件 append，崩溃处理器又调用 `add()`。

## 硬约束（违反会破坏可交付性）

1. **不要改包名** `com.jiuguan.ailink`，**不要改签名**（`keystore/*.jks`），否则无法覆盖安装。
2. **不要回退 Room 版本号**（当前 v4，有 `MIGRATION_3_4`）；回退会导致降级打不开库。
3. **不要改动 proot 启动参数** 中的五条硬约束（nativeLibraryDir 真实路径、`/dev/shm` 绑定顺序、OneBot 客户端禁止设 OkHttp `pingInterval`、长任务必须在前台服务、assets 里的 rootfs 不能改名）。
4. **不要在容器运行中删除 `rootfs`**，那是用户 350MB 的运行时。
5. 改动要小而可回滚；每改一处，说明它对应哪个证据。

## 交付要求

1. **根因**：一句话，附证据（栈帧或日志行）。
2. **改动清单**：文件 + 行为变化 + 为什么这样改能消除该根因。
3. **验证**：连续 10 次「停止 → 启动」+ 断网 30 秒恢复，均不闪退；`adb logcat -b crash` 无新增。
4. **如果最终判定不是代码缺陷**（例如 native 崩溃、系统限制），明确说明，并给出规避方案。
5. 若改了 Kotlin，请跑 `./gradlew :data:testDebugUnitTest :engine:testDebugUnitTest` 并报告结果。
