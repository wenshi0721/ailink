# 配置说明：QQ 接入与 AI 服务

本文对应 Android 客户端「接入助手」本次配置改造（未发布版本）及之后的界面。目标是把原先需要理解
OneBot、WebSocket、OpenAI 协议才能完成的配置，收敛成「选接入方式 → 填最少信息 →
测试 → 保存」四步。

---

## 一、首次使用：三步

首页在流程未完成时会显示「开始使用」卡片：

1. **接入一个账号**：手机内置 QQ / 电脑桥接 QQ / 微信桥接 / 本地演示，四选一。
2. **配置并测试 AI 服务**：可套用厂商模板，也可手填任意 OpenAI 兼容服务。
3. **启动接入服务**：打开后账号保持在线，收到的消息自动交给 AI 回复。

卡片只给「当前这一步」显示操作按钮，已完成步骤标为「已完成」，不需要自己判断顺序。
第 2 步以**测试通过**为准，只填了地址不算完成。三步都完成后卡片自动消失；升级用户若存在
旧版 API 配置，会出现在首页「待处理」清单里。

首次启动写入的「演示账号」不计入第 1 步——它只用于验证自动回复链路，不代表已接入真实账号。

## 二、QQ 接入的四种方式

账号编辑页第一步即选择接入方式，选择后地址与令牌会自动填好，不再要求用户理解
「正向 WebSocket」等概念。

| 方式 | 适用场景 | 需要填写 | 备注 |
|---|---|---|---|
| 手机内置 QQ | 只有一台手机，不想开电脑 | 无需（自动填 `ws://127.0.0.1:3001`） | 首次需安装约 350 MB 运行时并扫码 |
| 电脑/服务器上的 QQ | 已有 NapCat / LLOneBot / Lagrange | 电脑内网 IP + 端口（默认 3001） | 也可用配对码一键导入 |
| 微信（桥接） | Windows 上已有微信 hook 桥接 | 电脑内网 IP + 端口（默认 3002） | 手机端无法直接运行微信协议端 |
| 本地演示 | 只想验证自动回复流程 | 无需 | 不连接任何真实平台 |

### 关于扫码

手机内置 QQ 首次登录必须用**另一块屏幕**上的手机 QQ 扫描二维码。原因是 QQ 对
PC 端登录授权禁止相册识别与长按识别，只能调用摄像头。应用已优先采用扫码这条
官方允许的路径，并提供「分享二维码到电脑」「保存到相册」两个入口。

局域网桥接则优先推荐**配对码**：`ailink://pair?platform=qq&host=...&port=...&token=...`
由 `tools/pairing/make-pairing.mjs` 生成，粘贴后自动填好地址与令牌并立即测试连通性。

### 配置状态

编辑页「② 填写账号」顶部会显示当前状态：

| 状态 | 含义 | 下一步 |
|---|---|---|
| 未配置 | 地址为空 | 选择接入方式或填写地址 |
| 未测试 | 还没点过测试 | 点「测试连接」 |
| 测试中 | 正在握手 | 等待结果 |
| 测试成功 | WebSocket 握手成功 | 可保存并启动 |
| 测试失败 | 握手失败 | 按提示修正地址/令牌/网络 |
| 已保存未测试 | 配置已落库但未验证 | 建议补测 |
| 无需测试 | 本地演示 | 直接保存 |

测试结论按账号持久化，重新进入页面仍能看到；地址、令牌或接入方式一改，旧结论
自动作废。

## 三、AI 服务配置

### 字段

| 字段 | 必填 | 说明 |
|---|---|---|
| 配置名称 | 是 | 仅本地区分，例如「DeepSeek 主力」 |
| 接口地址 Base URL | 条件 | 留空 = 内置模拟回复；填写后走真实接口 |
| API 密钥 | 条件 | 认证方式为「不发送密钥」时可不填 |
| 模型名称 | 条件 | 需与服务商控制台的模型 ID 完全一致 |
| 协议类型 | 否 | OpenAI 兼容 / 自定义路径，默认前者 |
| 接口路径 | 否 | 留空自动补全；自定义协议必须填写 |
| 认证方式 | 否 | `Authorization: Bearer` / `x-api-key` / 不发送 |
| 自定义请求头 | 否 | 每行 `名称: 值`，可覆盖认证头 |
| 请求超时 | 否 | 10–180 秒，默认 60 |
| 失败重试 | 否 | 0–3 次，仅对网络错误、429、5xx 生效 |
| 启用 | 是 | 停用后任何账号都不会使用 |
| 设为默认 | 否 | 同一时间只有一份；账号未绑定配置时使用 |
| 温度 / 最大 Token / 系统提示词 | 否 | 与改造前一致 |
| 图片识别 | 否 | 自动探测模型是否接受图片内容块 |

请求参数方面，`temperature`、`max_tokens` 已是独立字段；响应体按 OpenAI 结构解析。
若接入非 OpenAI 协议，实现 `AiProvider` 时一并实现自己的请求体与响应映射即可，
业务层与配置存储不需要改动。

### 地址拼接规则

所有请求地址统一由 `AiEndpoint` 生成，顺序如下：

1. 填了「接口路径」→ 以用户值为准（相对路径拼在 Base URL 后，完整 URL 直接使用）；
2. 未填路径且地址已以 `/chat/completions` 结尾 → 原样使用；
3. 未填路径且地址已带版本段（`/v1`、`/v3`、`/v4`、`/openai`、`/compatible-mode/v1`）
   → 补 `/chat/completions`；
4. 其余 → 补 `/v1/chat/completions`（兼容旧配置）。

编辑页「高级设置」里会实时显示**实际请求地址**，不必再猜。

### 厂商模板

内置 DeepSeek、通义千问、Kimi、智谱、豆包方舟、硅基流动、腾讯混元、OpenAI、Ollama。
模板只做**预填**：新增配置不会默认套用任何厂商，也不会自动启用。用户点选后才会
写入对应地址与模型，且仍可自由修改。

### 默认配置与生效顺序

运行期解析配置的规则（`AiRepository.resolve`）：

1. 账号显式绑定且该配置**已启用、非待确认** → 使用它；
2. 账号未绑定 → 使用**已启用**的默认配置；
3. 否则 → 内置模拟回复。

解析**不会**在绑定配置被停用/删除时静默换用其他配置。这是有意为之：旧接口或
失效密钥不应在用户不知情时继续被调用。

### 密钥安全

- 密钥在写入数据库前用 Android Keystore 托管的 AES-GCM 加密，前缀 `enc1:`；
- 旧版本遗留的明文密钥仍可读取，下次保存自动转为密文；
- 系统密钥被重置（恢复备份、清除凭据）时解密失败，界面提示重新填写，**不会**
  把密文当密钥发出去；
- 密钥不会出现在日志与导出文件中。

## 四、旧配置迁移（数据库 v4 → v5）

升级后首次启动会自动执行迁移，只做**加列**，不删除任何账号、消息或配置。

迁移对 AI 配置的处理：

1. 新增协议、路径、请求头、超时、重试、启用、默认、测试结论等列；
2. **所有 `baseUrl` 非空的旧配置被置为停用（`enabled = 0`）并标记「待确认」**；
3. 内置模拟回复（地址为空）不受影响，仍可用；
4. 不自动设置默认配置。

界面上会看到：

- 首页「开始使用」卡片提示「有 N 个旧版 API 配置待确认」；
- 「AI 服务」页顶部横幅列出数量，提供「逐个核对」与「全部确认启用」；
- 待确认配置在账号选择列表里不可选，运行时不会使用。

确认方式（任选其一）：

- 打开配置 → 核对地址、密钥、模型 → 打开「启用此配置」→ 保存；
- 在列表中直接把开关拨到启用（会弹窗二次确认）；
- 确认无误后使用「全部确认启用」（会提示风险）。

确认后 `needsReview` 清除，配置正常参与运行。日志中会记录启用/停用动作
（`[ai] AI 配置 <id> 已启用`）。

> 迁移不会尝试"猜测"哪些旧配置仍然有效。是否继续使用旧接口，必须由用户显式决定。

## 五、错误提示对照

| 提示 | 原因 | 处理 |
|---|---|---|
| 密钥无效或无权限（HTTP 401） | Key 错误/过期/不属于该地址 | 重新粘贴 Key；确认 Base URL 与 Key 同一服务商 |
| 接口路径不存在（HTTP 404） | 地址少了 `/v1` 或路径写错 | 在「高级设置」里核对实际请求地址 |
| 请求被拒绝（HTTP 400） | 模型名不存在/参数不支持 | 对照控制台的模型 ID |
| 请求过于频繁或额度不足（HTTP 429） | 限流/余额不足 | 稍后重试或更换配置 |
| 域名解析失败 | 地址拼写错误/断网 | 检查域名与网络 |
| 无法连接到服务器 | 端口不对/服务未启动 | 检查端口与桥接端进程 |
| 请求超时 | 网络慢/模型响应久 | 调大超时或换更快模型 |
| 本机端口未监听 | 内置 QQ 未启动 | 运行时页启动 QQ 并扫码 |
| 目标端口拒绝连接 | 电脑 NapCat 未启动/防火墙 | 启动 NapCat，放行 3001 |
| 认证失败（WebSocket） | token 不一致 | 复制桥接端 token 重填 |

## 六、操作流程与恢复路径

### 账号：一次点击完成「测试 + 保存」

- 底部主按钮「保存并开始使用」会在保存前自动跑一次连接测试，不需要先点测试再点保存；
- 测试通过 → 直接保存并按需启动服务；
- 测试失败 → 弹窗给出原因，可选「返回修改」或「仍然保存」，已保存的配置可稍后在账号列表修复；
- 保存成功后不再直接退出，而是显示结果页：账号、连接结论、实际使用的 AI 配置、服务状态；
  主按钮为「启动接入服务」，服务已在运行时为「完成」；
- 返回时若有未保存修改，会先确认「放弃修改 / 继续编辑」。

### AI：保存并测试，失败留在本页

- 主按钮「保存并测试」；「仅保存」用于先存草稿；
- 失败不会退出页面，错误与修正建议就在结果横幅里，改完可直接重测；
- 保存后顶部显示「已保存」及是否已成为默认配置，底部按钮变为「完成」；
- 名称可留空，自动按模型名或域名取名，不再因为名称没填而卡住。

### 首页：当前该做哪一步

- 「开始使用」只给当前步骤加操作按钮，已完成步骤显示「已完成」；
- 「待处理」只列必须动手的问题：连接异常的账号、待确认的旧配置、未测试的当前 AI；
- 服务开关打开但没有可接入账号时，卡片显示「空转中 / 现在收不到任何消息」，
  不再显示「账号保持在线」这种与实际不符的状态。

### 失败后的恢复入口

- 账号连不上：首页当前账号卡片与账号列表直接显示原因归类（端口未监听 / 令牌被拒 / 超时 /
  地址解析失败 / 路径不是 OneBot 接口…）与「怎么改」，点「去修复」回到编辑页；
- 消息页被首页的「当前账号」过滤时，筛选栏出现「只看 xxx ✕」，点一下恢复全部会话，
  「清除筛选」也会一并取消账号过滤；
- 聊天记录清空、删除账号、停止 QQ 均需确认；删除账号额外提供「改为停用」作为不丢数据的替代。

## 七、回滚

### 仅回滚配置（推荐）

不需要降级 APK：

1. 在「AI 服务」里停用新配置、重新启用需要使用的配置；
2. 如需回到纯本地：把所有配置停用（或在账号上选择「内置模拟回复」）；
3. 账号页可随时切回旧地址与令牌，修改后重新测试即可。

### 降级到 v1.1.5 及更早版本

数据库已升级到 v5，旧版本只认识 v4。旧版本使用 `fallbackToDestructiveMigration`，
遇到更高版本的库会**清空并重建数据库**，表现为账号、AI 配置、聊天记录全部丢失。

因此降级前必须：

1. 在「设置 → 消息记录」确认无需保留历史，或先导出日志留档；
2. 记录当前 AI 配置的 Base URL、模型名（密钥需另行保存，界面不回显完整值）；
3. 卸载当前版本后安装旧 APK（避免直接覆盖触发降级异常）；
4. 重新添加账号、重新扫码登录、重新填写 AI 配置。

> 回滚到旧版本等于重新配置一遍，这是数据库版本单向升级的代价；请优先使用
> 「仅回滚配置」的方式。

## 八、手动验证清单

无自动化 UI 测试，发布前按以下路径手测：

1. **全新安装**
   - 首页出现「开始使用 0/3」；
   - 新增账号默认选中「手机内置 QQ」（已装运行时时）或「电脑上的 QQ」；
   - 默认地址不再出现 `192.168.1.10` 这类示例 IP。
2. **QQ 引导**
   - 选「本地演示」→ 保存并开始使用 → 首页显示 1/3、2/3、3/3 变化；
   - 选「电脑上的 QQ」填错误端口 → 点「保存并开始使用」→ 自动测试失败弹窗，
     选「返回修改」停留在表单，选「仍然保存」进入结果页；
   - 选「电脑上的 QQ」不填地址 → 点测试 → 提示「请先填写有效的 ws://」；
   - 填错误端口 → 提示端口拒绝连接与排查步骤。
3. **AI 配置**
   - 新增配置不再预填任何厂商地址；
   - 不填名称保存 → 自动按模型名取名，不阻塞保存；
   - 填 `https://api.deepseek.com/v1` + 错误 Key → 测试返回 401 与处理建议；
   - 打开高级设置，实际请求地址显示 `/v1/chat/completions`；
   - 保存后列表出现「默认」「未测试/测试通过」标签；
   - 点「保存并测试」且 Key 错误 → 停留本页，显示 401 与处理建议，底部仍有「仅保存」；
   - 复制配置 → 生成「xxx 副本」，不继承默认身份；
   - 停用默认配置 → 默认标签消失，账号回退到内置回复。
4. **迁移**
   - 用 v1.1.5 建一份远程 AI 配置并绑定账号；
   - 覆盖安装新版本 → 「AI 服务」出现待确认横幅，配置为停用；
   - 不确认时发消息 → 走内置模拟回复，日志提示「没有可用的 AI 配置」；
   - 确认启用并测试成功 → 自动回复恢复。
5. **操作逻辑**
   - 首页「开始使用」只有当前步骤有按钮；第 2 步在 AI 未测试前保持未完成；
   - 关闭总开关 → 首页三步引导回到「启动接入服务」一步，且不出现重复的待处理项；
   - 打开总开关但所有账号停用 → 服务卡显示「空转中」，并提示收不到消息；
   - 首页选中某个账号后进入「消息」→ 出现「只看 xxx ✕」，点击后恢复全部会话；
   - 聊天页「更多 → 清空聊天记录」先弹确认；
   - 编辑账号改一个字段后按返回 → 弹「放弃未保存的修改？」；
   - 运行时页底部为「接下来 3 步」实时清单，登录后按钮变为「已登录，回账号页测试连接」；
   - 「停止 QQ」先确认，取消后进程仍在运行。

6. **密钥**
   - 保存配置后，用 `adb shell run-as com.jiuguan.ailink` 查看数据库，
     `apiKey` 应为 `enc1:` 开头；
   - 重启应用后编辑页仍能正常测试（解密可用）。
