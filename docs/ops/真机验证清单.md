# 真机验证：具体操作步骤

目标：在真实 arm64 手机上确认容器链路可用，并回传诊断报告。
预计耗时 3 分钟。

- 安装包：`release/接入助手-1.0.18-debug.apk`（39 MB，已内置 Ubuntu arm64 运行时）
- 包名：`com.jiuguan.ailink.debug`（与正式包可并存）
- 要求：**arm64 手机**（2019 年后机型基本都是），Android 8.0 以上

---

## 一、把 APK 放进手机（三种方式任选）

### 方式 A：微信文件传输助手（不需要任何开发工具）

1. 电脑微信 → 搜索「文件传输助手」→ 点「发送文件」；
2. 选择 `release/接入助手-1.0.18-debug.apk` 发送；
3. 手机微信打开「文件传输助手」→ 点这个文件 → 右上角「…」→ **用其他应用打开** → 选择「安装包」或「文件管理」；
4. 进入安装界面 → 「安装」。

### 方式 B：USB + adb（已装 Android SDK 的话最快）

```bash
# 手机开启：设置 → 关于手机 → 连点版本号 7 次 → 开发者选项 → USB 调试
adb devices              # 首次需在手机上点「允许」
adb install -r release/接入助手-1.0.18-debug.apk
```

### 方式 C：数据线 / 云盘

把 APK 拷到手机任意目录（如下载目录），用「文件管理」点开安装。

---

## 二、安装被拦截怎么办

| 提示 | 处理 |
| --- | --- |
| 「未知来源应用」 | 点「设置」→ 允许来自此来源的安装 |
| 华为/荣耀「纯净模式」 | 设置 → 系统和更新 → 纯净模式 → 退出后重装 |
| 小米「MIUI 优化」拦截 | 设置 → 应用设置 → 授权管理 → 允许安装未知应用 |
| 「应用未安装」或「签名冲突」 | 先卸载旧的同包名应用（`com.jiuguan.ailink.debug`）再装 |
| 提示「该应用存在风险」 | 选「仍要安装」，这是调试签名导致的常规提示 |

## 三、执行自检（具体点击路径）

1. 桌面找到 **「接入助手」** 图标（蓝色气泡 + 绿色圆点），点开；
2. 底部导航最右 → **「设置」**；
3. 「配置」卡片第三行 → **「手机内置运行时（QQ）」**；
4. 看第一屏并记下两个值：**设备架构**、**Android 版本**；
5. 点下方 **「运行执行自检」**，等 2–5 秒；
6. 页面出现结果卡片后，点 **「复制诊断报告」**（按钮会变成「已复制到剪贴板」）。

## 四、对照预期结果

| 检查项 | 正常表现 | 异常说明 |
| --- | --- | --- |
| 系统架构 | 绿色，`arm64-v8a` | 红色说明不是 arm64，这条路不成立 |
| 可执行入口（busybox） | 绿色，显示 `libbusybox.so` 路径与大小 | 红色 = APK 未正确解压 native 库 |
| 容器引导（proot） | 绿色，`libproot.so`（arm64 约 250 KB） | 红色 = 装配失败 |
| execve 结果 | **「execve 成功」**，输出含 `proot 5.1.107.98` | 见下 |
| Linux rootfs | 红色（预期） | 尚未安装，属正常 |
| NapCat 运行时 | 红色（预期） | 尚未安装，属正常 |

异常输出的含义：

| 输出 | 含义 | 处理 |
| --- | --- | --- |
| `library "libtalloc.so" not found` | 依赖没被链接器找到 | 把报告发我，我调整加载方式 |
| `Bad system call` | 被 seccomp 拦截 | 厂商 ROM 限制，需换方案 |
| `Permission denied` | 厂商禁止执行应用内二进制 | 该机型不适合这条路 |

## 五、把结果发我

直接粘贴剪贴板内容即可，格式大致如下：

```
AiLink 运行时诊断
ABI=arm64-v8a Android=14
nativeDir=/data/app/.../lib/arm64
[OK] 系统架构: arm64，支持内置 QQ 运行时
[OK] 可执行入口（busybox）: .../libbusybox.so（1004 KB）
[OK] 容器引导（proot）: .../libproot.so（250 KB）
[NO] Linux rootfs: 未安装（预期目录 .../files/runtime/rootfs）
[NO] NapCat 运行时: 未安装（预期目录 .../files/runtime/napcat）
execLevel=OK
--- exec ---
执行目标：.../libproot.so
启动方式：native 库路径直连（LD_LIBRARY_PATH 指向同目录）
退出码：0
输出：proot 5.1.107.98 ...
```

顺带告知手机型号与系统版本（如「小米 14 / HyperOS 2」），后面容器保活要按厂商策略调。

## 六、自检通过后，我接着做的六步

| 步骤 | 具体做法 | 验收标准 |
| --- | --- | --- |
| 1 | ✅ 已完成：内置 Ubuntu 22.04 arm64 rootfs（27 MB），App 内解包到 `filesDir/runtime/rootfs` | 目录内存在 `bin/sh`、`etc/os-release` |
| 2 | ✅ 已完成（模拟器验证）：`proot -0 --rootfs ... --bind /dev /proc /sys` 进入容器 | `uname -a` 返回 Linux aarch64 |
| 3 | 容器内安装 QQ Linux arm64（约 120 MB）与 NapCat（约 40 MB） | `/opt/QQ/qq` 存在且可执行 |
| 4 | 用 `xvfb-run` 起虚拟屏，启动 QQ 与 NapCat，开启正向 WS | 容器内 `:3001` 监听 |
| 5 | App 读取容器内 `qrcode.png` 投到界面，扫码登录 | 界面出二维码，扫码后状态变「在线」 |
| 6 | 前台服务托管容器进程，异常退出按退避重启 | 冷启动到出码 ≤ 60 秒，挂机 72 小时不掉线 |

每完成一步，APK 会同步更新，你在真机上点一次自检就能看到进度条推进。
