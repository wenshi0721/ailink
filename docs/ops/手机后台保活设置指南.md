# 手机后台保活设置指南

> 适用对象：接入助手 AiLink（`com.jiuguan.ailink`）及一切需要 7×24 常驻后台的 Android 应用。  
> 覆盖范围：Android 8.0 – 16，EMUI / HarmonyOS 2–4、MagicOS、MIUI / HyperOS、ColorOS / OxygenOS / realme UI、OriginOS / Funtouch OS、One UI、Flyme、MyOS / RedMagic OS、MyUX / ZUI、ZenUI / ROG UI、HiOS / XOS、Pixel 与类原生。  
> 更新日期：2026-10-23。**各厂商菜单名称随版本调整频繁，路径以实机为准；找不到时在设置顶部搜索框搜「电池」「自启动」「后台」，这是最快的方式。**

---

## 〇、结论先行

Android 原生只提供一层限制（Doze + 应用待机），国内厂商在其上又叠了两到三层自研管控。**只做应用内的「忽略电池优化」不足以保活**，必须同时满足四个条件：

| # | 条件                   | 谁来做                 | 不做会怎样                    |
| - | -------------------- | ------------------- | ------------------------ |
| 1 | 应用被排除在电池优化 / Doze 之外 | 应用内入口 + 用户确认        | 息屏后 CPU 休眠，长连接心跳停摆       |
| 2 | 应用允许自启动（含开机、被清理后拉起）  | 仅用户手动（厂商权限，应用无法自授权） | 重启后不恢复；被杀后不再自愈           |
| 3 | 后台活动 / 耗电策略设为「无限制」   | 仅用户手动               | WakeLock 被系统强制回收，前台服务被冻结 |
| 4 | 最近任务列表加锁             | 仅用户手动               | 用户「一键清理」时被误杀             |

四项全部完成，国产 ROM 上的后台存活时间可从「息屏 5–15 分钟」提升到「数小时至数天」。**但没有任何设置能保证 100% 不被杀**——内存极度紧张、系统升级、长时间未交互仍可能回收，因此应用侧必须具备自愈能力（本项目由前台服务 + `BootReceiver` 承担）。

## 一、三层拦截模型：先理解系统在拦什么

| 层级    | 系统机制                                           | 典型表现                 | AiLink 侧的对策                                            |
| ----- | ---------------------------------------------- | -------------------- | ------------------------------------------------------ |
| 进程层   | LMK 低内存回收、厂商「应用速冻 / 深度休眠 / 一键清理」               | 应用进程消失，容器内 QQ 一并退出   | 前台服务（`dataSync`）+ 通知常驻，降低优先级                           |
| CPU 层 | Doze、应用待机分桶（active → rare → restricted）、厂商省电策略 | 进程还在但线程冻结，收不到也发不出    | `PARTIAL_WAKE_LOCK` 保持 CPU 唤醒（`KeepAlive.kt`）          |
| 网络层   | Wi-Fi 省电模式、睡眠模式定时断网、省流量                        | WebSocket 半开，心跳超时后重连 | `WifiLock`（`WIFI_MODE_FULL_LOW_LATENCY`）+ JSON 心跳（25s） |

**关键认知**：前台服务只保证「进程不容易被杀」，**不保证 CPU 不休眠**。这是 `HANDOVER.md` E1 记录的根因，也是必须同时配置第 2、3 项的原因。

## 二、通用五步（任何机型都先做完这五步）

### 第 1 步：加入电池优化白名单

打开「接入助手」→ 底部「设置」→ 配置卡片 → **「息屏保持在线（电池白名单）」** → 系统弹窗选「允许」。

- 该入口走 `Settings.ACTION_REQUEST_IGNORE_BATTERY_OPTIMIZATIONS`，直接弹系统对话框，无需逐层找菜单。
- 弹窗没出现（部分 ROM 屏蔽了该 Intent）时，改走通用路径：`设置 → 应用 → 特殊应用权限 → 电池优化 → 所有应用 → 找到「接入助手」→ 不优化 / 允许`。
- 校验命令：`adb shell dumpsys deviceidle whitelist | grep ailink`，能看到包名即成功。

### 第 2 步：允许自启动

国产 ROM 的独立权限，各家入口见第三章。**这一步不做，重启手机后 `BootReceiver` 收不到 `BOOT_COMPLETED`，服务不会自动恢复。**

### 第 3 步：后台活动设为「无限制」

应用信息页 → 电池 / 耗电管理 → 选「无限制」「允许完全后台行为」「允许后台高耗电」中最接近的一项（措辞因 ROM 而异）。避免任何形如「智能限制」「优化」「受限」的默认值。

### 第 4 步：最近任务列表加锁

打开应用 → 进入多任务界面 → 对「接入助手」卡片执行加锁手势（长按 / 下拉 / 点锁图标，见各品牌细则）。锁定后卡片上会常驻一个小锁标记。**这一步专门防「一键清理」和上滑清后台的习惯动作。**

### 第 5 步：确认通知权限

Android 13+ 需授予通知权限（本项目已在 Manifest 声明 `POST_NOTIFICATIONS`）。前台服务的常驻通知被关闭后服务仍可运行，但用户失去「是否还活着」的可见性，排障成本显著上升。建议同时把该通知设为「静默 / 不响铃」，避免长期打扰。

## 四、分品牌操作细则

### 4.1 华为（EMUI 5–12 / HarmonyOS 2–4）

| 目标     | 路径                                    | 取值                                    |
| ------ | ------------------------------------- | ------------------------------------- |
| 应用启动管理 | 设置 → 电池 → 应用启动管理 → 找到「接入助手」           | 关闭「自动管理」→ 弹窗勾选**允许自启动、允许关联启动、允许后台活动** |
| 电池优化   | 设置 → 应用 → 应用管理 → 接入助手 → 耗电详情 → 应用启动管理 | 同上的手动三项                               |
| 息屏联网   | 设置 → 电池 → 更多电池设置 → 休眠时始终保持网络连接        | 开启                                    |
| 清理白名单  | 手机管家 → 清理加速 → 右上角设置 → 忽略名单 / 白名单      | 加入「接入助手」                              |
| 后台任务锁  | 多任务界面 → 上滑应用卡片 → 点右上角锁图标              | 出现小锁                                  |

**注意**

- 「应用启动管理」的三个开关必须**同时**打开；只开「自启动」不开「后台活动」，息屏后仍会被冻结。
- 华为的「纯净模式」只影响 APK 安装（会拦截未知来源），与保活无关；若安装被拦，需临时退出纯净模式。
- **HarmonyOS NEXT（5.x 及以后，纯血鸿蒙）已移除 AOSP 兼容层，无法安装 APK**，不在本指南支持范围。HarmonyOS 4 及之前仍可正常安装。

### 4.2 荣耀（MagicOS 6–10）

| 目标     | 路径                           | 取值                        |
| ------ | ---------------------------- | ------------------------- |
| 应用启动管理 | 设置 → 应用 → 应用启动管理（部分版本在「电池」下） | 手动管理：自启动 + 关联启动 + 后台活动 全开 |
| 电池优化   | 设置 → 电池 → 更多电池设置             | 关闭「睡眠模式」，开启「休眠时保持网络连接」    |
| 清理白名单  | 系统管家 → 清理加速 → 设置 → 白名单       | 加入应用                      |
| 后台任务锁  | 多任务 → 下滑卡片 → 锁图标             | 出现小锁                      |

**注意**：MagicOS 与 EMUI 同源，主要差异是入口从「电池」移到了「应用」。MagicOS 8 之后新增「智能省流量」，若开启会在后台限制联网，需在 `设置 → 移动网络 → 流量管理` 中把本应用设为「不限流量」。

### 4.3 小米 / Redmi / POCO（MIUI 12–14 / HyperOS 1–3）

小米系是回收最激进的阵营，**五处都要改**。

| 目标            | 路径                                       | 取值           |
| ------------- | ---------------------------------------- | ------------ |
| 自启动           | 设置 → 应用设置 → 授权管理 → 自启动管理 → 接入助手          | 开启           |
| 省电策略          | 设置 → 应用设置 → 应用管理 → 接入助手 → 省电策略           | **无限制**      |
| 电池总开关         | 设置 → 省电与电池 → 电池 → 省电模式 / 睡眠模式            | 全部关闭         |
| 神隐模式（旧版 MIUI） | 设置 → 省电与电池 → 神隐模式 → 应用配置 → 接入助手          | 无限制 / 关闭神隐模式 |
| 清理白名单         | 手机管家 → 应用管理 → 权限 → 自启动；手机管家 → 垃圾清理 → 白名单 | 均加入          |
| 后台任务锁         | 多任务 → 长按卡片 → 锁图标（或下拉卡片）                  | 出现小锁         |

**注意**

- 「省电策略」是核心，必须显式选「无限制」；默认的「智能限制」会在息屏约 10 分钟后冻结进程。
- 开发者选项 →「启用 MIUI 优化」关闭后可显著降低干预，但会连带影响分屏、权限弹窗、部分系统应用，**不建议普通用户操作**，仅在排障时临时验证用。
- 若开启了「应用双开」，分身实例是独立包名（如 `com.jiuguan.ailink.dualboot`），白名单需对分身再配一遍。
- HyperOS 2 起 `设置 → 应用设置 → 应用管理` 顶部有搜索框，直接搜「接入助手」比逐层点更快。

### 4.4 OPPO / 一加 / realme（ColorOS 12–16 / OxygenOS 12–15 / realme UI 3–6）

| 目标     | 路径                                     | 取值                        |
| ------ | -------------------------------------- | ------------------------- |
| 自启动    | 设置 → 应用 → 自启动管理（或 手机管家 → 权限隐私 → 自启动管理） | 开启                        |
| 耗电管理   | 设置 → 应用 → 应用管理 → 接入助手 → 耗电管理           | **允许完全后台行为**（旧版为「允许后台运行」） |
| 电池优化   | 设置 → 电池 → 更多设置 → 电池优化 → 接入助手           | 不优化                       |
| 应用速冻   | 设置 → 电池 → 应用速冻 → 接入助手                  | 关闭（该项会把长期未用应用彻底冻结）        |
| 睡眠待机优化 | 设置 → 电池 → 更多设置 → 睡眠待机优化                | 关闭                        |
| 后台任务锁  | 多任务 → 卡片右上角「⋮」→ 锁定                     | 出现小锁                      |

**注意**

- ColorOS 的「智能省电」会在电量低于 20% 时无条件限制后台，长时间挂机建议保持充电或关闭该模式。
- 一加 OxygenOS 的路径与 ColorOS 基本一致，但「自启动」位于 `设置 → 应用 → 自启动`，没有手机管家入口。
- realme UI 的「应用速冻」默认开启，是 realme 机型掉线最常见的原因。

### 4.5 vivo / iQOO（OriginOS 1–6 / Funtouch OS 10–14）

| 目标    | 路径                                                  | 取值               |
| ----- | --------------------------------------------------- | ---------------- |
| 自启动   | 设置 → 应用与权限 → 权限管理 → 自启动（或 i 管家 → 应用管理 → 权限管理 → 自启动） | 开启               |
| 后台高耗电 | 设置 → 电池 → 后台耗电管理 → 接入助手                             | **允许后台高耗电**      |
| 关联启动  | 设置 → 应用与权限 → 权限管理 → 关联启动                            | 允许（避免被其他应用拉起时被拦） |
| 睡眠模式  | 设置 → 电池 → 更多电池设置 → 睡眠模式                             | 关闭（夜间会断网）        |
| 后台任务锁 | 多任务 → 下滑卡片 → 锁图标                                    | 出现小锁             |

**注意**：vivo 的「后台耗电管理」在某些版本中叫「后台高耗电」，且分「智能管理 / 允许 / 禁止」三档，必须选「允许」。iQOO 机型额外有「Monster 模式」，开启时会提高后台优先级，但会显著增加耗电，不建议长期使用。

### 4.6 三星（One UI 5–8）

| 目标     | 路径                         | 取值                               |
| ------ | -------------------------- | -------------------------------- |
| 后台使用限制 | 设置 → 电池 → 后台使用限制           | 检查「休眠应用」「深度休眠应用」两个列表，把接入助手**移出** |
| 从不休眠   | 同上 → 从不休眠的应用               | 加入接入助手                           |
| 单应用电池  | 设置 → 应用 → 接入助手 → 电池        | **不受限制**                         |
| 自适应电池  | 设置 → 电池 → 更多电池设置 → 自适应电池   | 建议关闭（会按使用习惯限制低频应用）               |
| 后台任务锁  | 多任务 → 点应用图标 → 锁定此应用 / 保持打开 | 出现锁标记                            |

**注意**：三星的「深度休眠应用」会自动收纳 3 天未使用的应用，且**不会通知用户**。长期挂机的设备应把本应用显式加入「从不休眠」列表，仅靠单应用「不受限制」不够。

| 后台任务锁 | 多任务 → 长按卡片 → 锁定          | 出现小锁      |

### 4.8 中兴 / 努比亚 / 红魔（MyOS / RedMagic OS）

| 目标   | 路径                                | 取值             |
| ---- | --------------------------------- | -------------- |
| 自启动  | 手机管家 → 自启动管理                      | 开启             |
| 后台运行 | 设置 → 应用 → 应用管理 → 接入助手 → 电池 / 耗电管理 | 允许后台运行         |

| Power Marathon | 设置 → 电池 → Power Marathon                  | 关闭极限省电             |

### 4.12 Google Pixel / 原生与类原生（Nothing OS、索尼 Xperia、夏普 AQUOS、诺基亚）

| 目标    | 路径                         | 取值                                |
| ----- | -------------------------- | --------------------------------- |
| 电池优化  | 设置 → 应用 → 接入助手 → 电池 → 不受限制 | 或 `设置 → 应用 → 特殊应用访问 → 电池优化 → 不优化` |
| 自适应电池 | 设置 → 电池 → 自适应电池            | 建议关闭                              |
| 极致省电  | 设置 → 电池 → 极致省电 / 节电助手      | 挂机期间关闭                            |
| 索尼    | STAMINA 模式                 | 关闭，或把应用加入 STAMINA 例外              |

**注意**：Pixel 的应用待机分桶（active / working set / frequent / rare / restricted）由系统自动判定。可用 `adb shell am set-standby-bucket com.jiuguan.ailink active` 手动把应用钉在 active 桶（重启后失效），用于验证「掉线是否由待机分桶导致」。

## 五、容易漏掉的系统级开关

以下开关与「自启动 / 省电策略」不在同一页面，但任意一项开启都会让前面的配置失效。

| 开关                        | 位置          | 影响                                  |
| ------------------------- | ----------- | ----------------------------------- |
| 省电模式 / 低电量模式              | 设置 → 电池     | 全局限制后台同步与网络，挂机期间必须关闭                |
| 超级省电 / 极致省电               | 设置 → 电池     | 仅保留白名单应用，容器必死                       |
| 睡眠模式 / 夜间模式               | 设置 → 电池     | 定时断网断后台，夜间整段掉线                      |
| 智能省流量 / 流量节省              | 设置 → 移动网络   | 后台限制联网，表现为 WS 反复超时                  |
| 应用速冻（ColorOS / realme UI） | 设置 → 电池     | 长期未用即冻结                             |
| 深度休眠应用（One UI / HyperOS）  | 电池 → 后台使用限制 | 3 天未用自动收纳，且不提示                      |
| 应用分身 / 双开                 | 各 ROM 应用设置  | 分身是独立包名，白名单需重配                      |
| 开发者选项 → 后台进程限制            | 开发者选项       | 设为「不得超过 N 个进程」会**加剧**杀后台，必须保持「标准限制」 |
| 儿童模式 / 专注模式 / 游戏免打扰       | 各自入口        | 可能屏蔽通知与后台网络                         |
| 鸿蒙 NEXT                   | —           | 无 AOSP 兼容层，APK 无法安装，不适用             |

**关于「后台进程限制」的常见误区**：不少教程建议把开发者选项里的后台进程数调小以「省电」，这会让系统在超过阈值时优先杀掉常驻服务，与保活目标完全相反。保持默认「标准限制」。

## 六、验证：怎么确认配置真的生效

### 6.1 三层验证法

| 层级    | 验证动作                     | 通过标准              |
| ----- | ------------------------ | ----------------- |
| 进程层   | 息屏 30 分钟后回到应用，看「概览」页账号状态 | 仍显示「在线」，无需重新初始化容器 |
| CPU 层 | 息屏期间从另一台设备发一条 QQ 消息      | 30 秒内收到并自动回复      |
| 网络层   | 导出日志，检查 `[onebot]` 段落    | 无连续的「已连接 → EOF」循环 |

### 6.2 adb 校验命令

```bash
PKG=com.jiuguan.ailink          # debug 包为 com.jiuguan.ailink.debug

# 是否在 Doze 白名单
adb shell dumpsys deviceidle whitelist | grep ailink

# 前台服务是否在运行
adb shell dumpsys activity services $PKG | grep -i foreground

# 是否被系统强制停止过（stopped=true 表示被冻结/停止）
adb shell dumpsys package $PKG | grep -i stopped

# 应用待机分桶（active 最佳）
adb shell am get-standby-bucket $PKG

# 临时提升优先级用于对照实验（重启失效）
adb shell am set-standby-bucket $PKG active

# 查看 WakeLock 是否被系统持有
adb shell dumpsys power | grep -i "ailink"
```

### 6.3 本项目的日志关键字对照

导出路径：设置 → 排障 → 导出诊断报告 → 「会话日志（AiLink 侧）」段落。


| 日志 | 含义 | 处理 |
| --- | --- | --- |
| `[keepalive] qq 已获取 PARTIAL_WAKE_LOCK` | 保活锁获取成功 | 正常 |
| `[keepalive] qq 释放保活锁` **出现在息屏期间** | 锁被系统回收 | ROM 省电策略未放行，回到第四章重配 |
| `[onebot] 已连接` 后长期无 `断开` | 链路稳定 | 正常 |
| `[onebot] 已连接` → `EOFException` 每 20 秒循环 | 协议层 ping 被 NapCat 断开 | 属代码缺陷（见 `HANDOVER.md` E2），非本指南范畴 |
| `[onebot] 发送超时` | WS 半开 | 检查 WifiLock 与「休眠时保持网络连接」 |
| `[engine] 回复 成功` | 全链路通 | 正常 |
| 无任何 `[keepalive]` 记录 | 前台服务未启动 | 检查是否被「强行停止」，重新打开应用 |

## 七、故障对照表

| 现象 | 最可能原因 | 处理 |
| --- | --- | --- |
| 息屏 5–15 分钟必掉线 | 省电策略未设「无限制」 | 第 3 步；小米/realme 重点查「神隐模式 / 应用速冻」 |
| 重启手机后不自动恢复 | 自启动权限未开，或 `BOOT_COMPLETED` 被拦 | 第 2 步；检查是否曾有「强行停止」 |
| 白天正常，凌晨掉线 | 睡眠模式 / 夜间省电 | 关闭睡眠模式，或设为「充电时不受限」 |
| 通知栏没有常驻通知 | 通知权限被拒 / 通知被手动划掉 | 授予通知权限，清理后重启服务 |
| 应用在，但消息延迟数分钟才到 | 应用待机分桶降级（rare） | 关闭自适应电池；`am set-standby-bucket active` 验证 |
| 一键清理后再也不恢复 | 未加锁 + 自启动未开 | 第 2、4 步同时做 |
| 分身/双开里配置无效 | 分身包名不同 | 对分身实例单独走一遍全部步骤 |
| 电量消耗超过 10%/小时 | WakeLock 与 WifiLock 常驻 | 属预期代价（3–8%/小时），超出则检查是否有异常重连循环 |

## 八、耗电与取舍

`PARTIAL_WAKE_LOCK` + `WIFI_MODE_FULL_LOW_LATENCY` 常驻，实测代价约 **3–8% / 小时**（`README.md` 已知边界）。这一开销来自「打破深度休眠 + 保持 Wi-Fi 全速」，不是应用本身的业务逻辑开销，因此无法通过优化代码消除。

可选的三档折中方案：

| 方案 | 做法 | 掉线风险 | 适用 |
| --- | --- | --- | --- |
| 常驻 | 本指南全套配置 | 低 | 主力挂机，随时需要秒回 |
| 仅充电时常驻 | 关闭息屏保活，插电时开启 | 中（拔电即停） | 夜间充电挂机 |
| 分时段常驻 | 用自动化工具在指定时段开服务 | 高（时段外不收） | 只需工作时间在线 |
