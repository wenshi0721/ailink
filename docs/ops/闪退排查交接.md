## 2. 现象

- **容器关闭时 App 闪退**（用户原话："在容器关闭时 app 会闪退"）。
- 以前容器重启不频繁，影响可忽略；1.1.7 引入"网络恢复即重启容器"后，重启频率上升，闪退变得可感知。
- 崩溃发生在**容器停止/重启的时间点**，不是日常聊天过程中。
- 未取得任何 Java 堆栈（Android 崩溃只进 logcat，用户拿不到）。

## 3. 已排除项（不要重复排查）

| 排除项 | 依据 |
|---|---|
| WakeLock 未持有就释放导致 `under-locked` | `KeepAlive.release()` 内有 `isHeld` 判断 + `runCatching`；但见 §6 假设 A（竞态仍在） |
| 停止流程中某一步抛异常直接崩 | `shutdown()` / `onDestroy()` 每一步已 `runCatching` |

| 主线程读大日志导致 ANR/闪退 | 导出/复制已移到 IO 线程；界面摘要改用文件长度，预览只读尾部 16KB |

## 6. 待验证的假设（按可能性排序）

**A. `KeepAlive` 竞态**
`acquire()` / `release()` **没有 `@Synchronized`**（`KeepAlive.kt:27` / `:54`），且内部是"判空 → 赋值 → 加锁"的 check-then-act。
若 main 线程（`onDestroy`）与 IO 线程（重启流程）同时进入，可能出现 `WakeLock under-locked` 或拿到 null 引用。
验证：读代码确认是否存在并发调用路径；给两个方法加锁后再复现。

**B. 服务被重复 stop/start**
`[keepalive] ... 已获取` 在每次重启都出现，说明服务实例被重建。若某条路径在同一时刻既 `stopSelf()` 又 `startForegroundService()`，可能出现 `ForegroundServiceDidNotStartInTimeException`（Android 12+ 的 10 秒窗口）。
验证：在 `onCreate` / `onStartCommand` / `onDestroy` / `shutdown` 各加一行带 `hashCode()` 的日志，确认实例是否被快速连建。

**C. `stopForeground` 与 `stopSelf` 时序**
`stopForegroundCompat()`（`:1024`）用 `STOP_FOREGROUND_REMOVE`，随后 `stopSelf()`。若此时系统正在回收通知（Android 16 更严格），存在抛异常窗口。
验证：把 `stopForeground` 移到 `stopSelf` 之后再观察；或改用 `stopForeground(STOP_FOREGROUND_DETACH)`。

**D. Compose 侧崩溃**
`RuntimeScreen` 在服务状态变化时重组，读 `vm.logSummary()` / `vm.logTail()`（仍是主线程 IO）。若 `SessionLog.tail()` 在文件被 roll 的瞬间读到不完整 UTF-8，理论上不会崩，但值得排除。
验证：把这两个读取移出组合（用 `produceState`），观察是否仍崩。

**E. `SessionLog` 锁内 IO 死锁**
`add()` 是 `@Synchronized` 且锁内做文件 append；崩溃处理器里又调用 `SessionLog.add`。若崩溃恰好发生在 `add` 内部，可能死锁 → 表现为 ANR/黑屏被用户当成闪退。
验证：给 `appendToFile` 加超时或改为异步队列。

## 8. 如何拿到崩溃栈（第一优先级）

1. 构建并安装 1.1.7 的 debug 包（debug code 28，可覆盖已装的 27/28）：
   ```bash
   cd android && ./gradlew assembleDebug
   adb install --no-streaming -r app/build/outputs/apk/debug/app-debug.apk
   ```
2. 复现：进入运行时页 → 停止 QQ → 再启动（或断开网络等待自动重启）。
3. 闪退后重新打开 App → 运行时页底部「日志与诊断」→「导出日志文件」。
4. 在导出文件里搜索 `[crash]`。格式：
   ```
   [HH:mm:ss][crash] 未捕获异常 线程=main java.lang.IllegalStateException: ...
   [HH:mm:ss][crash]     at com.jiuguan.ailink...
   ```
5. 若 `[crash]` 为空，说明不是 Java 崩溃（可能是 native / ANR），改用：
   ```bash
   adb logcat -b crash -d > crash.txt
   adb shell dumpsys dropbox --print data_app_crash > dropbox.txt
   ```

## 10. 红线（不要动）

1. **包名与签名**：`com.jiuguan.ailink` + `keystore/*.jks`，改了就无法覆盖安装。
2. **数据库迁移**：当前 Room v4，已有 `MIGRATION_3_4`；不要回退版本号（会导致 downgrade 打不开库）。
3. **proot 五条硬约束**（见根目录 `HANDOVER.md`）：nativeLibraryDir 真实路径、`/dev/shm` 绑定顺序、OneBot 客户端禁止设 OkHttp `pingInterval`、长任务必须在前台服务、`jks` 资产不能改名。
